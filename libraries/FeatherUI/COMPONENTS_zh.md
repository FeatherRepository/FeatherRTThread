# FeatherUI 组件清单与实现边界

更新日期：2026-09-01

## 结论

FeatherUI 的 GPU 渲染内核已经可用，但此前缺少独立的可复用组件层。页面能够显示和交互，不等于按钮、列表、选择器等已经成为通用组件；旧场景中的不少控件仍是直接调用 `fui_painter_*` 拼成的页面私有实现。

组件层必须遵守以下边界：

- 组件只计算布局、命中几何和显示状态，并把图元追加到当前 FeatherUI display list；
- 组件不得直接调用 VG-Lite、不得自行提交 GPU、不得创建第二条渲染线程；
- 固定的是组件容量和产品设计下限，尺寸、颜色、状态、文本、列表数量和命中区域必须由运行时数据产生；
- 绘制和触摸必须共享同一组几何函数，不能分别维护像素坐标；
- 只实现 FeatherTalk 产品需要的组件，不为了追求“大而全”复制 LVGL 全部控件。

## 状态说明

- **已完成**：已经有公共 API，当前页面已开始使用，并有回归覆盖；
- **部分完成**：功能已经存在，但仍是页面私有实现，或缺少产品需要的重要状态；
- **未实现**：当前只能临时拼图元，或对应业务尚无可靠交互。

## 图标系统

唯一图标注册表已经落地在 `include/feather_ui_icons.h` 和
`src/fui_icons.c`：

1. 应用、设置分类、页面选项和状态图标拥有稳定且不复用语义的
   `fui_icon_id_t`；旧 `draw_icon(id % 10)` 路径已经删除；
2. 当前约 70 个图标由 GPU 线段/矩形图元直接生成，不在每帧解析 SVG，
   仍随当前帧的唯一 display list 提交；
3. 连续同色线段由 `fui_painter_line_batch()` 收集到显示列表自己的线段池，
   最多 8 段编码为一条 VG-Lite compound path，避免“图标唯一化”退化成大量
   独立 path；
4. Wi-Fi、蓝牙、旋转、存储、USB、音频、语言等常用语义已经具有独立几何；
5. 仍需把视觉要求更高的品牌/应用插图转成构建期 A8 mask/path，并增加构建期
   重复形状审计；这是资源精修，不再是 ID 体系缺失。

## 实现顺序

1. **第一批（已落地）**：Button、List Row、Switch、Slider、Progress、Text Field、Scrollbar、UTF-8 文本测量；迁移重复实现。
2. **第二批前半（已落地）**：唯一图标注册表、Radio Group、Segmented Control 和 Select Popup；音频、UAC、时区、语言、背景、Flash/SD 和相册来源已迁移。
3. **第二批后半（已落地）**：通用 Context Menu、通用 Dialog 描述符、Spinner/Busy Overlay 和 Toast/Snackbar；文件、格式化、删除、错误反馈、相册加载和剪贴板动作已开始使用。
4. **第三批（当前下一步）**：Virtual List、Gallery Grid、Thumbnail、文件多选、设备卡和存储分区视图。
5. **第四批**：文本换行/省略、完整焦点模型、中文输入法、页面/键盘/模态转场。
6. **第五批**：图像缩放/平移、媒体进度、录音波形以及受 Wi-Fi/蓝牙底层服务约束的扫描结果组件。

暂不计划实现与当前产品无关的通用表格、复杂图表、桌面窗口管理器和 Web 风格布局引擎；出现明确业务需求后再纳入，避免组件库无边界膨胀。
