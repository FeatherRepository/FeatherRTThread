## 1. 系统形态

```
            ┌─────────── 子板（功能模块，插载板）───────────┐
            │  HiFi音频   本地音频   WiFi   屏幕   SD/eMMC   │
            │  USB+PMU-A(OTG) 或 USB+PMU-B(磁吸)  [传感器…]  │
            └──────────────────┬───────────────────────────┘
                               │ 板级连接器
            ┌──────────────────┴───────────────────────────┐
            │  载板（无功能，纯互连 + 电源分配 + 电平转换）     │
            └──────────────────┬───────────────────────────┘
                               │ 2× DF40C-80DS（BTB）
            ┌──────────────────┴───────────────────────────┐
            │  Edgi-Talk_Core 核心板（E84 + 存储 + 时钟 +      │
            │  PDM麦×2 + AMIC前端RC + 1.8V电源，固定不动）     │
            └──────────────────────────────────────────────┘
```

- **载板原则**：本身不具备功能，只完成核心板与各子板的互连、电源分配、必要的 1.8V↔3.3V 电平转换
- **子板 A/B 是二选一的电源变体**（同一卡位，不同产品形态）：整机只有一块电池，由所插的 PMU 子板管理

## 3.1 音频子板（两块独立子板）

> 曾考虑"A/B 同卡位两版本"，因 HiFi 需要**全双工 I2S**（方便测试带回采 ADC 的 codec）改为两块独立子板；整机形态 A = 只插本地音频，形态 B = 两块都插。
>
> ⚠️ **TDM 分配的原因**：TDM0 的 RX_FSYNC 引脚（P21.5）被核心板占用（MEMORY_RST，不出 BTB），所以 TDM0 只支持**共享时钟全双工**（RX_CTL.MODE=2，RX 吃 TX 主模式内部时钟，数据只需 RX_SD=P21.4——该脚在 BTB 上）；**独立时钟全双工只有 TDM1 能做**（TX+RX 八脚全在 BTB）。HiFi 要测各种 codec（含异时钟场景）故用 TDM1。

| 子板 | 功能块 | 接口 | 说明 |
|---|---|---|---|
| **本地音频子板** | 本地喇叭 | TDM0 TX（P21.1/21.2/21.3 + P12.3） | 播放本来就不需要 RX；I2S→Class-D（MAX98357A）或 AB 类（MD8002），电源走载板 5 V/VSYS |
| | 震动马达 | 二选一：DRV2605L（I2C 触觉驱动，挂主 I2C P8.0/8.1）或 1× TCPWM GPIO + NMOS 直驱 ERM/LRA | 官方 SoM 预留过 MOTOR_CTL_GPIO（P8.2/P14.7），可参考 |
| | 控制 | 主 I2C（P8.0/8.1，1.8 V） | 与传感器子板共总线 |
| **HiFi 音频子板** | HiFi codec | **TDM1 全双工**：TX_SCK/FSYNC/SD=P11.0/11.1/11.2、TX_MCK=P11.7；RX_MCK/SCK/FSYNC/SD=P11.3/11.4/11.5/11.6 | 可测 ES8388 这类"DAC+ADC"全双工 codec；独立干净模拟电源；MCK=12.288 MHz 基准整数分频 |
| | 时钟共享注意 | ES8388 类 codec 回放/录音共用一组 BCLK/LRCK，而 E84 TDM1 的 TX/RX 时钟是独立引脚 | 两种接法都支持：①codec 共享时钟——板上 0Ω 短接 RX_SCK/RX_FSYNC 到 TX 时钟线（RX 配从模式）；②异时钟——TX/RX 各自独立（TDM 块支持 TX/RX 独立分频器、各自可主可从、4 kHz~96 kHz，见数据手册 §5.15.2），按被测 codec 的接口形式选择 |

全双工带来一个回采通路的新用途：HiFi 子板可以兼做**测试子板**——codec 的 ADC 路径能验证 TDM1 RX、做环路自检。

## 3.2 WiFi+BT 子板（统一规格）与蓝牙通话

- 数据：WiFi 走 SDIO（SDHC0，1.8 V）；BT 走 UART（P10.0~10.3，带流控）
- 控制：WL_REG_ON/BT_REG_ON/WL_HOST_WAKE/BT_HOST_WAKE/WL_DEV_WAKE/BT_DEV_WAKE——普通 GPIO，从空闲池分配（P10.4~10.7 + P13 组）
- **蓝牙通话（HFP）语音通道**：⚠️ **E84 没有对外 PCM 总线**（片上"PDM/PCM 块"是麦克风的 PDM→PCM 转换器，不是 PCM 接口；BSP 引脚表无 PCM 复用）。CYW55512 模组的 PCM 口对端无脚可接；其 TDM 口又需要占用 E84 的 TDM 块（两路已分给音频）。
  **结论：PCM 不引出。需要通话时走 eSCO/WBS over HCI（UART/SDIO）软件方案**——零引脚成本，代价是 CPU 参与语音编解码转发。该功能标记为**可选软件特性**，硬件不留接口
- 模组选型参考：CYW55512（VDDIO=1.8 V 直连，BAT=3.3 V，32.768 kHz 睡眠时钟自带）

## 4. 电源架构与契约

- 电池只挂在 PMU 子板（A 或 B）上 → 子板输出系统轨 → 载板分配
- 核心板：**VIN 3.0~5.0 V**（5 针）、**VDDUSB_3V3**（必供，两块子板都用 USB）、回供 **VDD_1V8** 给载板小电流 1.8 V 负载
- 载板自产 **3.3 V**（子板供电、电平转换 VCCB）；HiFi 子板的干净模拟电源另计
- 休眠策略：PMU 子板决定整机低功耗下限（NPM1300 方案 ≈ µA 级；注意核心板自身 TPS63802 IQ 11 µA 是这套体系的功耗地板，见约束文档 §5）
- 无外设供电时序要求

## 5. 硬约束速查（设计时不能违反）

1. 全部 IO 1.8 V 逻辑；3.3 V 器件必须电平转换（IO6 口除外——可做 R6 改造选 3.3 V）
2. 存储固定 128Mb QSPI + 128Mb HyperRAM，不可扩展；扩容走 SD/eMMC 子板
3. eMMC 8-bit 模式占用调试 UART（P6.4~6.7）
4. sdhc1 卡检测用 GPIO（P7.4 没过 BTB）
5. TDM0 无法全双工（P21.5 不出核心板）——只播放无影响
6. WiFi 控制脚（REG_ON/WAKE×6）从空闲 GPIO 池分配，P11 已给 TDM1
7. Ethernet 不可用（与 TDM1/BT 冲突）
8. BTB 为 2× DF40C-80DS（0.4 mm，0.3 A/针），SMT 工艺
