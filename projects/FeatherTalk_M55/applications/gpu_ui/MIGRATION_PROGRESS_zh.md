# FeatherTalk GPU 原生 UI 迁移进度

更新日期：2026-09-01

## 当前结论

产品工程已经从默认 LVGL 启动路径切换到 FeatherUI。当前固件可以构建、烧录并在真实 E84 板卡启动 GPU 原生桌面；最终 ELF 不再包含 `lv_` 符号。旧 `applications/ui/` 源码和业务服务仍保留，作为页面行为与视觉迁移的基准，但不会进入当前固件。

当前已经进入第八阶段：旧 UI 的 17 个页面路由、主要手势和现有业务服务已接回 FeatherUI；中文简体字形图集、UTF-8 混排缓存、JPEG/BMP 预览、覆盖式软键盘、文件长按操作、固定容量动画调度器、稳定语义图标，以及 Button 到 Toast 的第二批公共组件也已迁移。完整组件审计见 [FeatherUI 组件清单](../../../../libraries/FeatherUI/COMPONENTS_zh.md)。仍未完成的是虚拟列表、缩略图网格、文件多选、页面转场、PNG 解码、中文输入法、真实媒体解码以及 Wi-Fi/蓝牙扫描服务；这些缺口不能因为“页面已经可进入”而被写成已完成。

## 已完成

- 独立 `libraries/FeatherUI`，无 LVGL 头文件或对象依赖；
- 固定容量不可变 display list；
- 每帧先收集全部任务，再统一编码；
- 每帧一次 `vg_lite_finish()`、一次 submit、一次 complete 的硬合同；
- 避免 VG-Lite scissor dirty 导致的逐命令隐式 flush；
- 两张 512-stride、480×800 RGB565 framebuffer；
- GPU 后台绘制、DC 前台直接扫描、frame-done 换址；
- UI/GPU 单线程，触摸 I²C 独立采样并通过消息队列投递；
- 状态栏、Start Tiles、三键导航以及 17 个页面的统一 8 层路由；
- 普通点击直接打开应用，600 ms 长按才进入 Tile 编辑；
- Tile 本体跟手移动/四角双向缩放、桌面边界约束、松手就近吸附及冲突 Tile 最近空位让位；
- Tile 长按后本体脉冲、松手后选中 Tile 与让位 Tile 的吸附动画；选中 Tile 始终最后绘制，操作箭头固定在逻辑框内；
- 从顶部跟手的快捷设置/通知面板、松手展开/收起、通知队列、未读数、左右滑删和全部清除；
- 通知面板松手目标同时依据距离和拖动速度，展开/关闭由统一属性动画完成；
- 设置分类与显示、声音、Wi-Fi、蓝牙、存储、USB、时间语言、个性化、系统信息、关于页面；
- 文件根目录、Flash/SD 浏览、目录进入/返回和长按操作菜单；
- 文件菜单的打开、剪切、复制、粘贴、重命名、删除和新建目录，绘制与触摸共用同一组动态矩形；
- 相册独立入口、图片筛选、JPEG/BMP GPU 预览、前后切换、设为壁纸和删除；
- 录音设备选择/开始/停止，媒体曲目状态、前后切换、播放状态和实际输出音量控制；
- 格式化、文件/照片删除使用统一全屏模态层；Flash/SD 格式化必须经过两级确认，模态期间输入不会穿透到底层页面；
- 文件粘贴、重命名、新建目录以及录音设备/启动/停止失败会显示本地化结果和错误码，不再静默忽略；
- 离开录音页时检查录音生命周期；正在启动或录音时先停止，停止失败则留在原页并反馈错误；
- FeatherUI 0.5 新增 Button、List Row、Switch、Slider、Progress、Text Field、Scrollbar 和 UTF-8 文本测量公共 API；
- 设置、搜索、文件、相册、键盘和模态层已开始使用公共组件；Slider 绘制和触摸映射共享同一几何；
- FeatherUI 0.6 新增 Radio Group、Segmented Control 和 Select Popup；音频、UAC、时区、语言、背景、Flash/SD 与相册来源不再依赖“点击循环下一个值”；
- 新增约 70 个稳定 `fui_icon_id_t`，应用、设置分类、选项和状态图标已删除 `id % 10` 的临时复用路径；
- 图标线段使用 display list 自有固定 segment pool，连续同色线段批成 compound path，保持一帧一次 GPU submit；
- `feather_ui_stats` 输出双 framebuffer 的运行时地址、尺寸、stride 和字节数，显存抓取不再依赖随链接布局变化的旧固定地址；
- 音量、输入增益、输出格式、背光、IPC 快捷开关、USB MSC/UAC、双存储设备和 A/B 偏好存储服务绑定；
- 302 个当前产品中文字符的构建期 A8 字形图集，以及中英文整串 A8 GPU 缓存；
- 屏幕宽高、状态栏、导航栏、行布局、磁贴网格、通知面板、键盘、媒体面板、相册查看器和文件菜单均由运行时 surface 尺寸计算；
- 磁贴吸附、冲突避让、底部坑位、缩放角区与屏幕边界共用运行时网格，不再回落到 480×800 旧坐标；
- 音频采样率、位深和声道枚举来自 `sound0` 驱动能力；启动时读取当前 DAC 格式并应用本机持久化配置；
- 背光百分比从 PWM 实际配置读取，UI 0–100% 动态映射到硬件 50–100% 安全占空比；
- 图片缓存固定的是 660 KiB GFX SRAM 预算，解码 stride 按请求宽度动态做 32 字节对齐，不再固定为 480×704；
- `stats/bench/pause` 板端诊断；
- OpenOCD 暂停后读取两张显存，确认首版画面完整且没有边界脏块。

### 第五阶段动画系统

- 新增固定 48 槽、无堆分配的 `fui_animation`，支持五种定点缓动、延迟、替换、取消、重复和往返；
- 动画只修改场景属性并触发 dirty，所有活动属性仍在同一帧收集前统一更新，不会拆分 GPU 命令链；
- Tile 长按脉冲限制在自身逻辑框内；四角缩放箭头不随脉冲漂移，避免重新引入导航栏、滚动条和相邻 Tile 的绘制污染；
- Tile 松手后才确认最近合法坑位并启动吸附，让位 Tile 仅在确认落位后移动；位置缓动禁止越过桌面边界；
- 通知面板保持触摸阶段逐点跟手，松手后再按距离/速度选择展开或收起；横向通知删除与纵向面板拖动通过触摸阈值分流；
- 板端统计增加动画活动数、历史峰值、启动、完成和取消次数；自动回归验证动画最终归零和每帧单次 GPU 提交合同。

### 第六阶段安全交互与页面生命周期

- 新增确认、最终确认和结果消息三种模态视图，统一标题、说明、目标对象、错误码和动作按钮；
- 模态层在键盘、通知面板之后收集，使用同一张整帧显示列表绘制遮罩、面板和按钮，不创建第二条 GPU 提交链；
- 对格式化执行两级确认，对文件和照片删除执行一级确认；取消、Back 和导航返回只关闭模态，不触发底层页面动作；
- 文件和相册删除完成后统一刷新目录、图片缓存和壁纸偏好，已删除的当前壁纸会安全回退到纯色背景；
- 录音页增加离开钩子，避免路由已经离开但录音任务仍在后台无提示运行；
- 自动回归新增确认推进、取消、导航拦截、错误消息关闭及四组动态 surface 的模态边界检查。

### 第七阶段基础组件层

- 新增 `feather_ui_components.h` 和 `fui_components.c`；所有组件保持立即式、固定状态描述符和零堆分配；
- List Row 统一标题、详情、禁用状态、Chevron 和 leading 插槽，产品图标通过 callback 绘制，组件库不依赖页面或应用 ID；
- Button 统一四种视觉类型、状态颜色和 UTF-8 动态居中；软键盘、相册来源/操作和模态按钮已迁移；
- Switch、Slider 和 Progress 使用动态 bounds；Slider 的轨道、Thumb 与坐标到数值换算来自同一描述符；
- Text Field 统一文本、占位符、焦点边框和光标；搜索框与软键盘输入框已迁移；
- 页面 Scrollbar 根据当前 viewport、content、offset 计算 Thumb，只有内容实际超出视口时才收集图元；
- 自动回归增加 ASCII/CJK 文本测量、Slider 端点/中点映射和 Scrollbar Thumb 几何检查。

### 第八阶段选择组件与语义图标

- 新增 Radio Group、Segmented Control、Select Popup 描述符，以及每个选项/分段的公共矩形和点命中 API；禁用候选项绘制为不可用并拒绝命中；
- 本地音频与 UAC 的采样率、采样深度和声道候选项直接来自现有驱动能力，当前组合不支持的候选项在弹窗中禁用；
- 时区、语言和背景改为一次可见全部候选项的 Select；Flash/SD 存储设备与相册来源改为 Segmented Control；
- 新增 `feather_ui_icons.h`/`fui_icons.c`，用稳定语义 ID 取代数字取模图标。图标只向当前 painter 追加图元，不持有业务状态、不直接调用 VG-Lite；
- 显示列表增加固定容量线段池和 `fui_painter_line_batch()`；一组图标连续线段最多 8 段编码为一条 VG-Lite compound path，避免每条线成为独立 path；
- 自动回归增加 Radio、Segmented、Select 的动态几何/禁用命中、图标 ID 有效性和中英文切换选择流程，当前板端为 86 pass / 0 fail。
- 通用 Context Menu 已替换文件页私有菜单，公共 Dialog 描述符已替换格式化/删除/结果消息的私有布局；相册加载使用 8 相位 Spinner，复制/剪切/粘贴使用自动消失 Toast；
- 远程事件回放揭示输入队列此前从未被消费：RT-Thread 5 的 `rt_mq_recv()` 成功返回消息字节数，旧代码却仅在返回 `RT_EOK(0)` 时分发。修复后板端为 `queued=1 / dispatched=1 / failed=0`，真实触摸和 `feather_ui_event` 共用的队列路径恢复；
- 显存抓取进一步发现相同 ASCII 字符串跨字号复用缓存时沿用了首次 `render_scale`；修复后 Select 中当前时区与其他时区字号一致。当前自动回归为 90 pass / 0 fail。

### 第九阶段字体与触控精度

- 删除当前 FeatherUI 固件中的 5×7 ASCII 点阵和独立旧 CJK atlas，改为构建期生成的统一 Noto Sans SC A8 产品 atlas；当前为 398 字形、129,600 字节；
- atlas 保留一套 18 px 母版，正文、普通标题和大标题分别通过 GPU 双线性采样得到约 14/18/27 px，避免三套常驻 atlas 导致 GFX 内存溢出；
- 双 GPU command buffer 从每个 256 KiB 调整为 224 KiB；当前最密集弹窗实测命令峰值约 67 KiB，仍有超过三倍余量；
- 触控初始化读取控制器量程，当前真机为 `1124 × 1124`，分别缩放到 LCD 物理坐标后再执行旋转映射；旧实现直接裁到 `480 × 800`，是边缘坐标失真和触点偏离的直接原因；
- ST7102 单点采样从每次读取 80 字节缩减为 16 字节，利用低有效 IRQ 避免无新帧时反复 I²C 访问；滤波死区从 3 px 缩到 1 px，释放确认从 3 帧缩到 2 帧；
- 输入队列从 16 增至 32，输入线程优先级高于 UI/GPU 线程，并新增最近/最大事件延迟统计；串口注入回归为 2/2 ms；
- Tile 移动、缩放与页面滚动不再依赖累积 delta：移动/缩放以按下锚点计算绝对目标，滚动以最后已处理坐标计算。这消除了消息合并或暂时延后时控件漂离手指的问题；
- 本轮板测为 `90 pass / 0 fail`，17 页面可进入，Home 连续 60 帧为 64.0 FPS，60 submit / 60 complete / 0 violation。

### 第二阶段渲染优化

- 收集阶段剔除 alpha 为 0 的矩形、线段和文本，不再为完全透明图元生成 GPU 命令；
- 将相邻、同色、完全不透明的矩形和线段合并为复合 path，严格保持原有绘制顺序，不跨越半透明命令重排；
- 复合 path 按 VG-Lite 规范使用重复 `MOVE` 开启各子路径，并且只在整条 path 末尾写入一个 `END`；
- 建立整串文本 A8 GPU 缓存，一段文本只需一次纹理 blit；超出缓存尺寸或裁剪范围的文本仍可回退到逐字形路径；
- FeatherUI 帧内延迟 VG-Lite 的逐次全 D-Cache 维护，在整帧命令编码结束、唯一一次 GPU 提交之前统一完成 Cache 维护；默认 VG-Lite 行为不变；
- 增加 clear/path/blit 调用数以及 collect、encode、GPU execute、render、present 分项统计；
- 第二阶段真机复测保持每帧一次 submit、一次 complete，且显存可见区域与优化前逐像素一致。

### 第三阶段交互迁移

- 新增 `feathertalk_gpu_scene.c`，业务页面不直接调用 VG-Lite，只生成 FeatherUI 绘制任务；
- 页面 ID 与旧实现一一对应：Home、Search、System、Settings、Media、Recorder、Gallery、Files、About 及 8 个设置子页；
- 输入层增加 600 ms 长按事件和 16 ms 动画节拍；无变化时仍由 dirty gate 阻止无意义重绘；
- Back 优先返回文件父目录，否则弹栈；Home 清空到根路由；Search 独立入栈；
- 快捷设置通过 M55 IPC 服务读取 M33 能力/连接状态；背光直接调用本机 PWM 驱动，继续执行 UI 0–100% 到硬件 50–100% 的安全映射；
- `feather_ui_test` 覆盖 17 个路由、长按编辑、移动、缩放、吸附、滚动、Back/Home/Search、通知栏拖动和通知滑删，并以只读方式探测音频、录音、USB、Flash、SD 服务；
- `feather_ui_page 0..16` 可直接打开任意迁移页面；`feather_ui_event down|move|up|tap|long x y [dx dy]` 通过 UI 消息队列注入触摸事件，便于逐页显存抓取、交互回放和性能回归。

### 第四阶段动态数据与资源约束

FeatherUI 现在执行以下硬编码规则：

- 允许固定：芯片/面板客观规格、寄存器位、协议值、Flash 分区边界、静态 SRAM 预算、路由/队列容量上限以及明确的产品默认主题；
- 必须动态：屏幕尺寸和布局坐标、触摸命中区域、可见行数、通知容量、磁贴坑位、文件/设备列表、存储容量和使用量、设备在线状态、音频格式能力、当前音量/背光、图像目标尺寸；
- 静态应用描述符只保存产品数据（名称、页面、颜色和默认网格跨度），不保存最终像素坐标；
- 绘制区域和事件命中区域必须调用同一个几何函数，禁止分别维护两套坐标；
- UI 不再自建音频格式表，UAC 和本地声音设置共同枚举 `feathertalk_audio` 返回的驱动能力；
- 设置入口改为单一描述符表，名称、详情、图标与路由不再依靠多组平行数组和重复下标；音量/增益上限同样由音频驱动上报；
- 录音设备行数、媒体控制行、磁贴默认行数、相册/文件动作数和字体字符数均从实际数据或数组长度推导；
- FeatherUI 输入阈值由 surface 尺寸和引擎配置生成；600 ms 长按和 60 Hz 目标帧率属于明确的产品交互常量。

## 真实板端基线

测试硬件：PSE846GPS2DBZC4A B0，480×800 MIPI-DSI 面板，GPU2D 200 MHz，M55 400 MHz。

首个桌面场景约 142–143 条显示列表命令：

| 指标 | 结果 |
| --- | --- |
| GPU 提交合同 | 120 帧 / 120 submit / 120 complete / 0 违约 |
| 每帧命令流 | 约 66.6 KiB |
| collect | 约 0.59 ms |
| render（含编码与 GPU 等待） | 约 22.12 ms |
| GPU 硬件忙时 | 约 3.78 ms |
| present | 约 0.33 ms |
| 当前连续吞吐 | 43.0 FPS（最终固件 120 帧复测） |

结论：GPU 本体没有饱和。首版的主要瓶颈是官方 VG-Lite API 对 142 个图元的 CPU 命令编码，render 阶段约 22.1 ms，其中 GPU 仅忙约 3.8 ms。第二阶段通过命令合并、整串文字缓存和每帧统一 Cache 维护显著降低了 CPU 开销，GPU 忙时基本不变。

## 第二阶段真机对比

以下结果均来自相同 E84 板卡和桌面场景。`path-only` 的“115”是高层 VG-Lite 调用数；整串文本缓存启用后，FeatherUI display list 为 71 条，实际高层 VG-Lite 调用为 45 次（3 clear / 29 path / 13 blit）。

| 阶段 | 吞吐 | 显示列表/高层调用 | 命令流 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 原始实现 | 约 43.0 FPS | 约 143 条命令 | 约 66.6 KiB/帧 | 逐字形 blit，未合并图元 |
| path-only | 41.6 FPS | 115 次高层调用 | 54,551 B/帧 | 相邻同色 opaque 图元合并为复合 path |
| text-run | 93.3 FPS | 71 条命令 / 45 次调用 | 41,152 B/帧 | 整串 A8 缓存，3 / 29 / 13 次调用 |
| 最终 cache-defer | 117.1 FPS | 71 条命令 / 45 次调用 | 39,904 B/帧 | 规范化 path，并将 Cache 维护合并到提交前一次执行 |

最终 `cache-defer` 版本的 240 帧连续基准：

| 指标 | 结果 |
| --- | ---: |
| collect | 433 us |
| encode | 4,047 us |
| render（含编码与 GPU 等待） | 7,718 us |
| GPU 硬件忙时 | 3,605 us |
| present | 282 us |
| VG-Lite 高层调用 | 3 clear / 29 path / 13 blit |
| GPU 提交合同 | 240 帧 / 240 submit / 240 complete / 0 违约 |
| 显存校验 | 相同状态下 480×800 全可见区域差异 0 像素 |

117.1 FPS 是显式 `bench` 连续重绘时测得的渲染吞吐，不代表系统空闲时持续满帧运行。默认运行采用 dirty-gated 策略：界面内容没有变化时不重复收集、编码和提交帧。

## 最新真机结果

固件已在同一块 PSE846GPS2DBZC4A B0 板上由 Infineon OpenOCD 写入并校验。M55 UART 为 COM17。

## 后续优化顺序

1. 补 Virtual List、相册缩略图网格、PNG 解码和大目录增量加载，只收集可见项目；
2. 建立设备卡、存储分区视图和文件多选/批量动作，并复用现有 Context Menu / Dialog；
3. 继续压缩语义图标 path 编码，并把视觉要求更高的 SVG 转成构建期 A8 mask/path；增加重复 ID/缺失资源检查；
4. 在现有 GPU 原生键盘上补中文输入、候选词和完整焦点切换；
5. 基于现有属性动画补页面 push/pop、模态层和键盘进出转场，但仍保持一帧一条 GPU 命令链；
6. 为音频、USB、存储等异步操作补进度、取消和最终结果状态，并把分项性能接入回归门槛；
7. 继续迁移 Wi-Fi 扫描、蓝牙设备列表和媒体解码等受底层服务进度约束的深层业务。

迁移期间禁止为了快速恢复功能而在 FeatherUI 帧内调用 LVGL，也禁止让业务页面直接调用 VG-Lite。所有绘制必须先进入 FeatherUI display list，统一由唯一渲染线程提交。
