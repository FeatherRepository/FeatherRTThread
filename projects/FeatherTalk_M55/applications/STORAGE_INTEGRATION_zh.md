# FeatherTalk 内置 Flash 与可移动存储接入

## 当前状态

内置 Flash 与 SD 卡均接通真实硬件链路，不是 UI 模拟数据：

1. 板级 `SDHC1` 以 4-bit 模式连接卡槽，RT-Thread MMC/SD 层负责枚举卡与分区。
2. SDK 公共文件系统服务 `libraries/Common/board/ports/filesystem/mnt.c` 监听插拔事件，自动把首个可识别 FAT 卷挂载到 `/sdcard`；拔卡时自动卸载。
3. 文件名使用 FatFS UTF-8 长文件名模式，最大长文件名为 255 字符。
4. FeatherTalk 产品层 `feathertalk_storage.*` 只依赖 DFS/POSIX 接口，提供卷状态、目录枚举、路径拼接、返回上级和文件头预览，不直接操作 SDHC 寄存器。
5. “文件”应用从根目录显示 `/flash` 与 `/sdcard` 两个设备目录。进入任一介质后显示真实挂载状态、总容量、可用空间、文件夹数和文件数；点击普通文件时，文本文件预览开头 383 字节，二进制文件只显示真实大小。
6. 页面打开期间每 500 ms 只检查挂载状态；只有插拔状态变化、进入目录或手动刷新时才重建列表，不在每帧扫描介质。
7. Settings 中的“存储”分类始终存在。页面以两张设备卡分别显示内置 Flash 与 SD 卡；选中后只展示该设备的卷容量、已用/可用比例条、短状态以及独立的浏览和格式化操作。未插卡时 SD 卡仍可被选中，但相关操作会安全禁用。
8. 外部 S25FS128S 的末尾固定 `0x60E00000..0x61000000`（2 MiB）作为内置 FAT 用户盘。它位于 M55 8 MiB XIP 槽和 256 KiB trailer 之后，容量与地址都不随当前固件大小变化。

当前 FatFS 配置支持 FAT12/FAT16/FAT32。没有启用 exFAT，因此 exFAT 卡不会被伪装成可用。产品设置页提供明确的手动格式化入口，但必须经过两次确认，不会因插卡、挂载失败或自动测试而自行擦除介质。

## 调试命令

```text
ls /sdcard
ls /flash
sdcard_umount
sdcard_mount
sdcard_mkfs ERASE-ALL
feather_usb status
feather_usb storage
feather_usb stop
```

拔卡前可执行 `sdcard_umount`。重新插入后正常路径由卡检测中断与热插拔线程自动恢复；`sdcard_mount` 只用于诊断。`feather_usb storage/stop` 与设置页使用完全相同的安全切换路径，供板端诊断和自动化验收使用。当前 SDK 的 MSH 没有实现 `df`，容量由文件应用和 System 页直接通过 `statfs` 获取。

`sdcard_mkfs` 不再接受无参数调用，必须逐字提供 `ERASE-ALL`。它与 UI 最终确认共用 `board_sdcard_format_fat()`：先确认 USB 未占用，再尝试卸载 `/sdcard`，最后只对物理设备 `sd` 执行整盘格式化并重新挂载。若文件仍被打开导致卸载失败，操作返回 busy，不进入擦写阶段。

## 磁盘管理与格式化

“存储”页以设备为操作目标，并在容量视图中区分物理设备与当前已挂载卷：

1. 顶部设备卡读取真实物理容量和挂载/USB 状态；Flash 与 SD 各自使用独立图标和选择状态，热插拔不会把当前选择强制跳回另一设备。
2. 详情区的大容量数字与比例条只使用当前挂载卷的 `statfs` 数据；物理容量仍保留在设备卡中。SD 多分区时不会把某个卷的剩余空间误画成整块物理卡的剩余空间。
3. 卷未挂载、介质缺失或由 USB 占用时，比例条明确降级为不可用状态，不把未知值伪装成“全部可用”。短状态只保留 FAT、挂载点、MBR/GPT 和分区数量。
4. “浏览文件”把文件应用直接打开到所选设备的 `/flash` 或 `/sdcard`；“格式化”只作用于当前选中的设备。Flash 格式化仅清除固定 2 MiB 用户盘，不影响固件或 SD 卡。
5. SD 本机格式化仍是整盘破坏性操作：删除全部现有分区并创建一个 FAT 兼容卷。Elm-FatFS 根据介质容量选择 FAT12/16/32；当前约 31 GB 卡会选择 FAT32。当前未实现 exFAT。
6. 第一次确认时即锁定 Flash/SD 操作目标，第二次确认再次说明不可撤销；最终按钮才启动后台格式化线程。格式化期间两个设备选择和操作按钮均禁用，完成后重新挂载。
7. UI 自动化分别选择两块设备、核对容量视图和操作门控，并打开确认框后取消，永远不触发最终擦除按钮；真实格式化只能由用户最终确认或在 MSH 输入 SD 的 `ERASE-ALL`。

电脑端同样可以格式化：启动 USB 存储后，MSC 导出的是完整物理 `sd`，Windows 磁盘管理或其他主机工具可删除/新建分区和格式化。完成后必须先在电脑上安全弹出，再在 FeatherTalk 中停止 USB 存储，才能恢复本机挂载。若电脑格式化为 exFAT/NTFS，电脑可以使用，但当前 FeatherTalk 文件应用不会挂载；要供两端共同访问，应使用 FAT32。

## USB Device MSC

原理图确认当前 Type-C 接口的产品级可靠路径是 USB Device；Host 所需的 VBUS 供电、角色切换与过流保护没有完成，因此设置页固定选择“设备”，并把“主机”显示为不可用，不会仅凭 SDK 存在 Host 示例就向用户开放。

存储器模式使用 CherryUSB Device MSC 同时接到内置 Flash 和真实 SD 块设备：

1. 当前双盘模式要求 `/flash` 与 `/sdcard` 均已挂载且 SD 仍在位；无卡时设置页仍能看到内置盘与 SD 卡槽状态，但不会启动一个容量无效的 SD LUN。
2. 启动前同时安全卸载 `/flash` 和 `/sdcard`，再把两个原始块设备独占交给 USB MSC。此时本机文件应用不再访问两块 FAT 卷。
3. LUN 0 是固定 2 MiB 内置 Flash，LUN 1 是完整物理 `sd`，电脑会枚举同一个 MSC 设备下的两个逻辑磁盘。SD 不会退化为只导出 `sd0` 分区，因此电脑仍可读取、重建或格式化整张卡。
4. Flash 块设备对上提供 512 字节扇区，对下以 64 KiB NOR 擦除块执行读-改-擦-写缓存；每个 USB WRITE 成功前强制同步缓存，避免主机数据只停留在 M55 RAM。
5. 点击“停止 USB 存储”后先停用 USB Device、同步并关闭两个块设备，再依次恢复 `/sdcard` 与 `/flash` 本机挂载。电脑正在写盘时不得复位、拔卡或强制切换模式。
5. 导出期间若检测到拔卡，服务会停止 MSC；设置页以 500 ms 状态监视器更新“等待主机/已连接/已枚举/错误”等状态，不在 UI 每帧轮询。

当前 VID/PID `FFFF:F501` 只用于开发板验证，量产前必须替换为正式分配的标识。USB Audio (UAC) 只在设置页列出并明确标记为不可用；它将在音频链路接入时单独实现，不与本轮存储器模式伪装成已完成。Host 模式继续禁用。

CherryUSB 默认 MSC 缓冲只有 512 字节，会把主机的连续请求拆成逐扇区 SDHC 操作。FeatherTalk 产品配置把缓冲提高到 64 KiB（128 个扇区），缓冲位于 USB DMA 数据区；`feather_usb status` 会报告读写操作数、累计字节、最大单次长度和实际缓冲大小。真机 64 MiB WriteThrough 顺序写从 `0.213 MiB/s` 提升到 `4.741 MiB/s`，约 22.3 倍；安全弹出并重新枚举以排除 Windows 文件缓存后，顺序读为 `10.098 MiB/s`。读回 SHA-256 与写入数据一致，临时文件删除后再次安全弹出、停止 MSC，并确认 `/sdcard` 恢复挂载。

## 设备 UI 配置与相册

固定 2 MiB Flash 用户卷同时承载普通用户文件和每台设备自己的 UI 配置：

1. 配置目录固定为 `/flash/.feathertalk`，相册和文件应用不展示这个私有目录。
2. `ui-config-a.bin` 与 `ui-config-b.bin` 是两个独立槽。记录采用显式小端序，包含 magic、schema、generation、完整 payload 和 CRC32；不把编译器结构体直接落盘。
3. payload 保存强调色、Start Tile 透明度、背景模式、12/24 小时制、固定时区、语言和一个规范化壁纸路径。修改后静默 2 秒再写入非活动槽，`fsync`、Flash 同步和回读校验均成功后才切换活动 generation。
4. 启动 USB MSC 前必须先冻结后台写线程并同步最新配置。停止 MSC、恢复 `/flash` 挂载后重新检查 A/B 槽；如果电脑格式化或删除了配置，设备以内存中的当前值自动重建记录。
5. 本机格式化 Flash 使用同一冻结/重建协议。格式化会删除 Flash 中的照片和旧配置文件，但不会影响固件、SD 卡或当前运行中的 UI；重新挂载后当前配置会重新落盘。
6. 自动 UI 测试开始时先同步真实配置并暂停持久化，结束时恢复快照。测试中的主题、语言和壁纸动作不会磨损 Flash，也不会把用户配置重置为默认值。

相册把 `/flash/Pictures` 与 `/sdcard/Pictures` 作为两个独立照片集合；介质已挂载且可写时自动建立 `Pictures`，不会浏览存储根目录或充当第二个文件应用。集合最多显示 64 张通过扩展名、文件大小、解码头和像素上限检查的 JPG/JPEG/PNG/BMP 图片。选为壁纸时只保存规范化路径：放在 Flash Pictures 的图片随设备长期保存；放在 SD Pictures 的图片拔卡后暂时回退为纯色背景，重新插卡后仍保留用户选择。PNG 解码需要整图内存，因此产品对 PNG 字节数和像素数设置了比 JPEG/BMP 更严格的上限。

精选壁纸包位于 `tools/freather/wallpapers`，包含三张适配面板原生分辨率的 480x800 JPEG。通过 USB MSC 或主机读卡器复制到 `/flash/Pictures` 后，即可在相册中选择并设为壁纸；原始素材与许可链接见[壁纸包 README](../../../tools/freather/wallpapers/README.md)。

## Files 文件与目录操作约束

文件应用的操作边界按“卷根”和“卷内项目”分开：

1. Files 最外层 `/` 只列出 `flash` 与 `sdcard` 两个设备项。设备项不是普通目录，长按会在 Files 当前页原地弹出对应卷的双重格式化确认；取消或执行后都不跳到 Storage 管理页。设备项不可复制、剪切、重命名或删除。
2. `/flash`、`/sdcard` 自身是受保护卷根。存储后端拒绝任何以卷根为源的删除和重命名，也拒绝包含 `..`、`.`、重复分隔符或越界路径的请求。
3. 卷内普通文件和目录统一支持打开、剪切、复制、重命名和删除；目录复制/删除递归深度上限为 12，避免畸形目录树无限递归。长按目录还可以直接在其中新建子目录或粘贴。
4. 长按当前目录空白区域提供新建目录和粘贴。文件名不得为空、不得是 `.`/`..`，不得以空格开头/结尾或以点结尾，并拒绝 `\\\"*/:<>?|` 及 ASCII 控制字符；同名目标不会被覆盖。
5. 同卷剪切优先使用原子 `rename()`；跨卷剪切先递归复制，成功后才删除源。任何子项失败都会回滚新目标。复制同名项目使用 `-copy`、`-copy-2` 等安全名称，目录不能粘贴进自身或后代。
6. 新建与重命名通过 UI 屏幕键盘输入；操作面板和确认面板仅暴露当前硬件已有的功能，不显示没有后端的分享、压缩、云盘或“发送到”。
