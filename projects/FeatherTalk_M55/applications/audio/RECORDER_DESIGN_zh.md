# FeatherTalk M55 录音应用设计

## 功能边界

录音机是与 Settings、Media、Gallery、Files 并列的独立应用。它只负责选择输入设备、
开始采集、显示录音时长和实时峰值、结束并保存录音，不把音频设备参数配置重复放入
应用；音量与输入增益仍由“设置 > 音频”管理。

当前板载输入如下：

| 输入 | RT-Thread 设备 | 当前状态 | 格式 |
| --- | --- | --- | --- |
| 双 PDM 麦克风阵列 | `mic0` | 已注册、可选择 | 16 kHz、双声道、16 bit PCM |
| AMIC2 模拟麦克风 | `amic0` | 驱动未实现，显式置灰 | 注册后由设备能力查询决定 |

录音服务不写死只能使用 `mic0`：设备卡与服务端共同按索引枚举，只有设备存在、具有
只读采集能力并且初始化成功时才允许选择。以后 `amic0` 注册后，录音应用不需要改变
交互流程。

## 页面与交互

- 页面顶部显示独立的录音机图标、名称和用途说明。
- 输入设备使用独立卡片与独立图标；当前选择以强调色边框表示，不可用设备置灰并标明
  “驱动不可用”。
- 中央区域显示 `MM:SS.d` 计时、0–1000 峰值条和圆形录音按钮。
- 待机时按钮为“开始录音”；采集中为“结束并保存”。停止阶段禁用重复操作，避免同时
  创建两个文件或重复关闭设备。
- 保存完成后显示完整原生路径和数据大小，并可跳转 Files 查看 `Recordings` 目录。
- 离开页面时若仍在采集，会请求停止并保存；后台线程负责完成 WAV 尾部更新，不让页面
  生命周期直接持有设备或文件描述符。
- 简体中文与英语文本均走全局语言切换，Feather、设备名和路径等产品/技术标识不翻译。

## 后台状态机

`feathertalk_recorder.*` 是与 LVGL 解耦的服务，状态为：

```text
IDLE/SAVED/ERROR -> STARTING -> RECORDING -> STOPPING -> SAVED
                                 |                    |
                                 +------ error -------+-> ERROR
```

开始录音前依次验证所选 Audio 设备和可写卷，分配工作线程后才进入 `STARTING`。工作线程
打开设备与目标文件、写入占位 WAV 头并进入 `RECORDING`。UI 线程每 160 ms 读取状态，
不会执行阻塞的 `rt_device_read()` 或文件写入。停止请求只设置状态和原子式停止标志；
工作线程关闭输入、回写最终头、`fsync()`、关闭文件后才发布 `SAVED`。

任一步失败都会关闭已打开的 Audio 设备和文件、释放缓冲区并删除不完整文件，最终错误码
保留在状态中。线程栈为 8 KiB，采集/写盘缓冲为 2 KiB。

## 文件与存储策略

- 目标卷按 `/sdcard`、`/flash` 顺序选择，卷必须已挂载且至少有 64 KiB 可用空间。
- 每个卷使用固定 `Recordings` 目录，文件名为 `REC_<启动 tick>_<序号>.wav`；序号避免
  同一 tick 重名。
- 格式是标准 RIFF/WAVE、PCM format 1、小端序，采样率、声道数和位宽来自所选设备的
  `AUDIO_CTL_GETCAPS`，不由 UI 猜测。
- 数据块最大为 32 bit RIFF 长度允许的范围；超过边界会停止并删除不完整文件。
- Internal Flash 作为兜底卷时仍遵守已有的固定 2 MiB 分区和双核 SMIF 保护；录音服务
  不把固件后的临时空白区当文件系统。

## 验证接口

板端提供两个 MSH 命令：

```text
feather_recorder_status
feather_record 2
```

`feather_record N` 使用当前选择的输入，等待设备真正进入 RECORDING 后录制约 N 秒，
并等待保存完成；最终时长允许多一个采集块的收尾粒度。状态输出包含设备格式、
时长、PCM 数据字节数、当前/整段最大峰值、卷和文件路径。保存态还会重新打开文件并
校验 `RIFF`、`WAVE`、`fmt `、`data` 标识、两个长度字段以及实际文件长度，打印
`wav=valid`。`maxpeak` 大于零可证明本轮收到过非零采样，但它不替代声学质量测试。

UI 自动化覆盖应用注册、页面创建、默认 `mic0`、两个独立选择卡、AMIC2 明确不可用、
开始/停止控件和页面资源释放。真实采集、文件头与数据量由上述 MSH 实板流程验证，避免
自动 UI 回归每轮永久产生录音文件。

## 后续工作

- 实现 AMIC2 RT-Thread Audio 驱动后解除第二输入设备置灰，并做模拟/数字输入切换回归。
- 文件名接入可靠 RTC 后，可在不改变目录和 WAV 合约的情况下改为本地日期时间。
- Media 增加 WAV 播放后，Files/录音机可以直接调用统一播放器。
- USB UAC 采集与本地录音共用输入设备时，需要增加显式的设备占用仲裁。
